# Infraestructura y tecnologías

## Servidores

- **Nginx** — Servidor web y proxy inverso para servir aplicaciones, gestionar tráfico HTTP/HTTPS y distribuir peticiones.
- **Linux** — Sistema operativo habitual para ejecutar servidores, aplicaciones y servicios de infraestructura.

## BBDD

- **MySQL 8.x** — Sistema gestor de bases de datos relacionales para almacenar y consultar información estructurada.
- **Percona Server for MySQL** — Distribución optimizada de MySQL orientada a rendimiento, disponibilidad y administración de bases de datos.
- **PostgreSQL** — Base de datos relacional avanzada utilizada para aplicaciones que requieren consultas complejas, integridad y extensibilidad.

## NO-SQL

- **Redis** — Almacén de datos en memoria utilizado principalmente para caché, sesiones, colas y operaciones de baja latencia.
- **MongoDB** — Base de datos documental NoSQL orientada a almacenar información flexible mediante documentos JSON/BSON.

## AMAZON AWS

- **Amazon Redshift** — Data warehouse cloud para analizar grandes volúmenes de datos mediante SQL.
- **Amazon S3** — Almacenamiento de objetos para documentos, ficheros, copias de seguridad y datos.
- **Amazon EC2** — Servicio de máquinas virtuales para ejecutar aplicaciones y servicios en AWS.
- **Amazon RDS** — Servicio gestionado para desplegar y administrar bases de datos relacionales.
- **Amazon CloudFront** — CDN de AWS para distribuir contenido desde ubicaciones próximas al usuario.
- **AWS Lambda** — Ejecución de código bajo demanda sin necesidad de administrar servidores.
- **Amazon CloudWatch** — Monitorización de aplicaciones, servidores, métricas, logs y alertas.

## CDN

- **Akamai** — Red de distribución de contenido para acelerar sitios web, aplicaciones y servicios digitales.
- **Cloudflare** — CDN y plataforma de seguridad para proteger y acelerar aplicaciones y sitios web.
- **Amazon CloudFront** — CDN integrada con AWS para distribuir contenido globalmente.

## 11.1 Concepto de programa informático

### Definición

Un **programa informático** es un conjunto ordenado de instrucciones que indica a un sistema informático qué operaciones debe realizar para conseguir un objetivo determinado.

Un programa puede recibir datos de entrada, procesarlos mediante unas reglas y producir unos resultados de salida.

### Elementos básicos

- **Entrada:** datos que recibe el programa.
- **Procesamiento:** operaciones realizadas sobre los datos.
- **Salida:** información o resultado generado.
- **Control:** estructuras que determinan el orden de ejecución de las instrucciones.

### Ejemplo

Un programa que calcula la media de tres notas:

1. Recibe las tres notas.
2. Suma sus valores.
3. Divide la suma entre tres.
4. Muestra la media.

## 11.2 Código fuente, código objeto y código ejecutable

### Código fuente

El **código fuente** es el conjunto de instrucciones escritas por el programador utilizando un lenguaje de programación.

Ejemplo:

```java
public class Hola {
    public static void main(String[] args) {
        System.out.println("Hola");
    }
}
```

### Código objeto

El **código objeto** es una representación intermedia generada a partir del código fuente durante determinados procesos de compilación.

### Código ejecutable

El **código ejecutable** es el código preparado para que pueda ser ejecutado por el sistema o por el entorno de ejecución correspondiente.

### Máquinas virtuales

Una **máquina virtual** proporciona un entorno de ejecución que permite ejecutar determinados programas independientemente de las características concretas del hardware.

Ejemplo:

- Java utiliza la **JVM (Java Virtual Machine)**.
- El código Java se compila a **bytecode** y posteriormente la JVM lo ejecuta.

### Flujo simplificado

```text
Código fuente
     |
     v
Compilación
     |
     v
Código objeto / bytecode
     |
     v
Entorno de ejecución
     |
     v
Programa en ejecución
```

## 11.3 Tipos de lenguajes de programación

Los **lenguajes de programación** permiten expresar algoritmos e instrucciones que posteriormente serán interpretados o traducidos para su ejecución.

### Según el nivel de abstracción

#### Lenguajes de bajo nivel

Están próximos al funcionamiento interno del procesador y del hardware.

Ejemplo:

- Lenguaje ensamblador.

#### Lenguajes de alto nivel

Utilizan estructuras y expresiones más próximas al lenguaje humano y permiten desarrollar aplicaciones con mayor nivel de abstracción.

Ejemplos:

- Java
- Python
- C#
- JavaScript
- Kotlin
- PHP

### Según la forma de ejecución

- **Compilados:** el código se transforma antes de su ejecución.
- **Interpretados:** un intérprete ejecuta las instrucciones mediante un entorno de interpretación.
- **Híbridos:** utilizan una fase intermedia y posteriormente un entorno de ejecución.

## 11.5 Fases del desarrollo de una aplicación

El desarrollo de software puede organizarse en diferentes fases. La forma concreta de organizar estas fases depende de la metodología utilizada.

### 1. Análisis

Se estudian las necesidades que debe resolver la aplicación y se identifican los requisitos.

**Ejemplo:** determinar qué debe hacer una aplicación para gestionar alumnos.

### 2. Diseño

Se define cómo se construirá la solución.

Puede incluir:

- Arquitectura.
- Componentes.
- Interfaces.
- Bases de datos.
- Diagramas.
- Flujos de información.

### 3. Codificación

Se transforma el diseño en código fuente mediante un lenguaje de programación.

### 4. Pruebas

Se comprueba que la aplicación funciona correctamente y que cumple los requisitos establecidos.

### 5. Documentación

Se genera información que facilita el uso, mantenimiento y evolución del software.

### 6. Explotación

La aplicación se pone a disposición de los usuarios y se utiliza en el entorno previsto.

### 7. Mantenimiento

Se realizan cambios posteriores a la puesta en funcionamiento:

- Corrección de errores.
- Adaptaciones.
- Mejoras.
- Nuevas funcionalidades.
- Actualizaciones.

### Ciclo simplificado

```text
Análisis
   ↓
Diseño
   ↓
Codificación
   ↓
Pruebas
   ↓
Documentación
   ↓
Explotación
   ↓
Mantenimiento
   ↺
```

En metodologías ágiles estas actividades pueden repetirse en ciclos cortos dentro de diferentes iteraciones o sprints.

## 11.6 Proceso de obtención de código ejecutable a partir del código fuente

El proceso depende del lenguaje y de la tecnología utilizada.

### Proceso general

```text
Programador
    |
    v
Código fuente
    |
    v
Compilador / intérprete / herramienta de construcción
    |
    v
Código intermedio o ejecutable
    |
    v
Entorno de ejecución
    |
    v
Aplicación
```

### Herramientas implicadas

- Editor de código.
- Compilador.
- Intérprete.
- Máquina virtual.
- Linker o enlazador, cuando corresponda.
- Depurador.
- Sistema de construcción.
- Gestor de dependencias.
- IDE.

### Ejemplo con Java

```text
Archivo .java
     |
     v
Compilador javac
     |
     v
Archivo .class
     |
     v
JVM
     |
     v
Ejecución
```

# 3) Diseño y realización de pruebas (Entornos de desarrollo)

## 13.1 Planificación de pruebas

La **planificación de pruebas** consiste en determinar qué se va a probar, cómo se va a probar, cuándo se realizará y qué resultados se consideran correctos.

### Elementos

- Objetivo.
- Alcance.
- Casos de prueba.
- Datos de entrada.
- Resultado esperado.
- Resultado obtenido.
- Criterios de aceptación.
- Recursos necesarios.

### Ejemplo

Para una función que calcula una media:

| Entrada | Resultado esperado |
|---|---:|
| 5, 5, 5 | 5 |
| 0, 10, 10 | 6,67 |
| -1, 1, 0 | 0 |

### Recurso

- [Planificación de Pruebas](https://www.jesusninoc.com/11/12/diseno-y-realizacion-de-pruebas-entornos-de-desarrollo/#Planificacion_de_Pruebas)

---

## 13.2 Tipos de pruebas

### Pruebas funcionales

Comprueban si la aplicación realiza correctamente las funciones requeridas.

**Ejemplo:** comprobar que el botón "Guardar" almacena los datos.

### Pruebas estructurales

Analizan la estructura interna del programa y sus caminos de ejecución.

### Pruebas de regresión

Comprueban que una modificación no ha introducido errores en funcionalidades que anteriormente funcionaban.

### Pruebas de caja negra

Se comprueba el comportamiento de la aplicación sin analizar necesariamente su implementación interna.

### Recurso

## 13.4 Pruebas de código: cubrimiento, valores límite y clases de equivalencia

### Cubrimiento

El **cubrimiento** mide qué parte del código o de los caminos de ejecución ha sido recorrida durante las pruebas.

Ejemplo:

```text
if (edad >= 18) {
    permitirAcceso();
} else {
    denegarAcceso();
}
```

Una prueba que solo utilice `edad = 20` no comprueba el camino correspondiente a menores de edad.

### Valores límite

Consiste en probar valores situados en los límites de los rangos aceptados.

Si una edad válida está entre 18 y 65:

- 17
- 18
- 19
- 64
- 65
- 66

### Clases de equivalencia

Los valores se agrupan en conjuntos que deberían producir comportamientos similares.

Ejemplo:

```text
Edad < 18       → no válida
18 ≤ edad ≤ 65  → válida
Edad > 65       → no válida
```

# 4) Optimización y documentación (Entornos de desarrollo)

## 14.1 Refactorización

La **refactorización** consiste en modificar la estructura interna del código sin cambiar su comportamiento externo esperado.

### Objetivos

- Mejorar la legibilidad.
- Reducir duplicación.
- Simplificar código.
- Facilitar el mantenimiento.
- Mejorar la organización.
- Preparar el código para nuevas funcionalidades.

### Ejemplo

Código repetido:

```text
calcularPrecioClienteA()
calcularPrecioClienteB()
calcularPrecioClienteC()
```

Puede estudiarse una reorganización para extraer la lógica común a una función reutilizable.

### Refactorización y pruebas

Las pruebas permiten comprobar que una refactorización no ha modificado accidentalmente el comportamiento esperado.

### Patrones habituales

- Extraer método.
- Renombrar variable.
- Extraer clase.
- Eliminar código duplicado.
- Simplificar condicionales.

### Herramientas

Muchos IDE incorporan operaciones automáticas de refactorización.

### Recurso

- [Refactorización. Concepto. Limitaciones. Patrones de refactorización más usuales. Refactorización y pruebas. ## 14.2 Control de versiones

Un **sistema de control de versiones** permite registrar los cambios realizados sobre los ficheros de un proyecto.

### Conceptos fundamentales

- **Repositorio:** lugar donde se almacenan y gestionan las versiones del proyecto.
- **Commit:** registro de un conjunto de cambios.
- **Rama (branch):** línea independiente de desarrollo.
- **Merge:** integración de cambios procedentes de diferentes ramas.
- **Clonado:** creación de una copia local de un repositorio.
- **Push:** envío de cambios al repositorio remoto.
- **Pull:** incorporación de cambios desde un repositorio remoto.

### Ejemplo con Git

```text
Modificar código
      ↓
git add
      ↓
git commit
      ↓
git push
      ↓
Repositorio remoto
```

### Herramientas

- Git.
- GitHub.
- GitLab.
- Bitbucket.

#### Ejemplo PowerShell: formulario para botones de prueba
```PowerShell
$buttons_functionslist=@(
	"Botón1",
	"Botón2",
	"Botón3"
	"Botón4"
	"Botón5"
)

$buttons_functionbuttoncount = $buttons_functionslist.count

$loop = 0

#Formulario
$Form = New-Object System.Windows.Forms.Form
$Form.Text="Formulario"
$Form.Size=New-Object System.Drawing.Size(500,500)
$Form.StartPosition="CenterScreen"

while($loop -lt $buttons_functionbuttoncount)
	{
	$thisbutton = New-Object System.Windows.Forms.Button
	[string]$thisbuttonname = $buttons_functionslist[$loop]
	$thisbutton.Text = $thisbuttonname
	$thisbutton.size = New-Object System.Drawing.Size(100,20)
	$thisbutton.Location = New-Object System.Drawing.Size(200,(20*$loop+1))
	$thisbutton.Add_Click({
	        Write-Host $this.Text
		})
	$Form.Controls.Add($thisbutton)
	$loop += 1
	}

$Form.ShowDialog()
```

## 15.1 Relación entre los conceptos

Una aplicación comienza con unas necesidades que deben analizarse. Posteriormente se diseña una solución, se codifica utilizando un lenguaje de programación y se construye mediante las herramientas correspondientes.

Una vez desarrollado el software se realizan pruebas para detectar errores y verificar los requisitos. El código puede refactorizarse y optimizarse, mientras que la documentación y el control de versiones facilitan su mantenimiento.

El proceso continúa después del despliegue mediante correcciones, actualizaciones y nuevas funcionalidades.

```text
REQUISITOS

    ↺
```
